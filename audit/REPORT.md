# Аудит GONE Player · 2026-10-05

Ветка `audit/gone-2026-10-05`, база `main` @ `cfa1f14`. Аудит сделан по коду и расчётом, без сборки: на Linux-машине нет Xcode и macOS SDK. Swift-код в ветку не коммитился. Исправления лежат патчами в `audit/patches/`, проверочные скрипты в `audit/verification/`.

## 1. Вердикт

1. **Битый или недокачанный хвост файла вешает плеер.** Интерфейс показывает «играет», звука нет, движок 24 раза в секунду перечитывает один и тот же нечитаемый кусок. Очередь дальше не идёт (находка Н6, патч 02).
2. **BPM врёт настолько, что сортировка и BPM-фильтр ошибаются.**
   - Быстрый проход выдаёт только значения с шагом 1,5–3 BPM: 128 → 129,2, 127 → 126,0.
   - Прямой бит на 95–110 BPM с шестнадцатыми хэтами часто превращается в ×4/3 (99 → 132,5).
   - DnB на диапазоне по умолчанию детектируется как 132–140 или 115–117.

   Всё это проверено расчётом (Н1–Н3, патч 01).
3. **Звук уходит туда, куда не ждёшь.**
   - Вынул наушники или звуковую карту: трек продолжает играть в динамики ноутбука (Н8).
   - Закрыл крышку: после пробуждения трек заиграет сам (Н21).
4. **Split Mode разъезжается.**
   - Плеер B привязан к устройству вывода, которое было у A в момент включения, и не следует за его сменой (Н9).
   - BPM и вейвформы в B замерзают на снимке момента включения (Н10).
5. **Длинные и «облачные» файлы.**
   - У часового микса вторая половина вейвформы пустая (Н20).
   - Файл-заглушка iCloud при выборе вешает интерфейс до полной загрузки (Н23, подтвердить на Маке).
   - Нечитаемый файл молча показывает «играет» (Н22).

## 5. Три большие доработки

### Доработка 1. Надёжное воспроизведение: один читатель, явный формат, бесщелчковые переходы

**Что меняется для диджея:**
- Любой файл (моно, 6/8 каналов, 96/192 кГц, часовой VBR MP3, файл на сетевом диске) играет или честно говорит «не могу».
- Хот-кью и перемотка без щелчков и провалов.
- Выдернутый кабель не ломает сессию.

**Файлы:** `GONE/AudioEngine.next.swift` (порядок узлов не меняется), `PlayerState+Playback.swift`, `TrackHeaderView.swift` (бейдж ошибки трека), `GONEApp.swift` (привязка колбэков).

**Риски:**
- Контракт потоков движка (`bufferQueue`, `playbackToken`) — самое чувствительное место. Любое изменение должно сохранить правило «каждая межпоточная операция перепроверяет токен».
- Конвертер добавляет CPU на старых MacBook.
- Fade-out перед `stop` откладывает перемотку на 5–10 мс: на это легко сделать гонку с повторным нажатием.

**План, каждый шаг на один вечер:**
1. Применить патчи 02, 03, 04, 13. Собрать. Ручные проверки П1–П5 из раздела 6.
2. **Один `AVAudioFile` на поколение** (по `token`), открывается на `bufferQueue`. Курсор `framePosition` продвигается последовательно, переоткрытие только после ошибки. Это убирает К-N8 и квадратичный поиск в VBR MP3 (П2).
3. **Явный формат воспроизведения**: стерео float32 на частоте файла. Если `processingFormat` другой (моно, многоканальный), конвертация через `AVAudioConverter` на `bufferQueue`. `playerNode` подключается всегда в этом формате. Это снимает подозрение П1.
4. **Бесщелчковый stop**: `seek` и хот-кью сначала ставят `gateNode` в ноль рампой примерно за 5 мс (у слайсера своя рамка — не конфликтовать: на время перехода он приостанавливается), затем `stop` и `schedule`. Fade-in уже даёт патч 03.
5. **Ошибка трека в UI**: состояние `.unplayable` в `Track` (сессионное, без базы), бейдж в заголовке и строке, ошибки чтения видны и без режима отладки.

### Доработка 2. BPM второго поколения: семейство темпа по полосам и регрессионный стенд

**Что меняется для диджея:**
- Сортировка по BPM правдива с точностью ±0,1 BPM (это уже даёт патч 01).
- DnB, брейки и 95–110 BPM определяются без выбора жанрового пресета.
- Пресеты остаются ручным уточнением, а не обязательным шагом.

**Файлы:** `LibraryScanner.swift`, `PlayerState+Analysis.swift`, `AnalysisCache.swift` (версия), новый `tools/bpm_bench/` (портированный стенд из `audit/verification/` плюс список эталонных треков владельца с известным BPM).

**Риски:**
- Регрессии в жанрах, где сейчас всё верно. Без реального корпуса улучшение не доказать.
- CPU: две полосы — это примерно двойная автокорреляция. Она дешёвая (vDSP), декодирование не меняется.
- Смена версии кеша вызывает однократный повторный анализ библиотеки.

**План:**
1. Применить патч 01. Прогнать реальный корпус владельца (12 эталонных треков и сколько найдётся сверх). Если брейки регрессируют, подобрать порог 0,5 в `windowVote` или вернуть спасатель только для широкого результата <95.
2. **Стенд в репозитории**: Python-порт как регрессионный тест (синтетика из `audit/verification/bpm_bench.py` + опционально WAV-корпус). Прогон до и после каждого изменения детектора.
3. **Онсеты по полосам**: бочка (40–150 Гц, однополюсные фильтры на 11 025 Гц) и малый барабан с хэтами (>1,5 кГц). Отдельные автокорреляции; период бита выбирается по согласию полос. Сильная доля бочки разрешает половину или двойной темп, полоса снейра даёт 2 и 4 и отличает DnB 174 от 4:5.
4. **Семейство темпа**: для кандидатов {T, 2T, T/2, 4T/3, 3T/4} сравнить корреляцию бочки на целых и половинных долях и выбрать максимально согласованный. Убрать отдельный «спасатель» и правило 95–145 перед глубоким проходом.
5. Поднять версию кеша и записать результаты стенда в `docs` (владельцем).

### Доработка 3. Скорость на 2000+ треках: сканирование и список без квадратичной работы

**Что меняется для диджея:**
- Папка на 2000 треков заполняется метаданными в разы быстрее.
- Список не подтормаживает при листании стрелками во время анализа.
- Повторный запуск с большой библиотекой не крутит диск.

**Файлы:** `PlayerState+Playlists.swift` (импорт), `PlayerState.swift` (индекс), `PlaylistView.swift` (`visibleTracks`), `AnalysisCache.swift` (формат и запись), `PlayerState+Analysis.swift` (приоритет видимых строк).

**Риски:**
- Инвалидация SwiftUI: кешированный `visibleTracks` должен сбрасываться на любую мутацию `tracks` и вкладок.
- Миграция формата кеша (старый JSON читать и переписывать).
- Крупные порции метаданных дольше держат UI без обновлений: показывать прогресс.

**План:**
1. **Кеш отсортированного списка**: `sortedTracks` мемоизируется по ключу (вкладка, ключ сортировки, направление, счётчик версий `tracks`). Вычисляется один раз на тело вью и передаётся в строки. `tracks(forPlaylistTabId:)` использует существующий `trackIndex`, номер строки передаётся вместо `firstIndex`. Это закрывает Н25.
2. **Импорт метаданных**: порции 16–32 с одной записью `tracks` на порцию (как уже сделано в анализе), слияние по словарю индексов вместо `firstIndex` внутри цикла (сейчас O(n²) на 2000 треков). Параллельность `readMetadata` до `analysisConcurrency`.

4. **Приоритет видимого**: анализ сначала обрабатывает строки в видимой области плейлиста (их id уже известны `PlaylistTracksPane`), потом остальное.
